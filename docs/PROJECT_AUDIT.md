# HERO WORLD 项目梳理与经典传奇对标审计

审计基线：2026-11-07  
仓库：`oneyi53/Legend53`  
引擎：Godot 4.7.2 / GDScript / 2D 等距 / Android 竖屏  
审计范围：当前 `main` 分支、场景结构、核心脚本、项目设计文档与 CI 配置。

## 1. 产品定位

HERO WORLD 应定位为原创的竖屏单机传奇类 ARPG。对标的是经典《传奇》的品类体验与循环，不是复制某一款商业游戏的素材或具体实现，也不是六人小队、放置卡牌或纯自动数值游戏。

核心循环：

城镇整备 → 野外探索 → 手动/自动刷怪 → 技能战斗 → 经验、金币与装备掉落 → 装备整理/强化/觉醒 → 挑战精英与 Boss → 解锁更高阶地图。

## 2. 当前项目结构

- `scenes/boot/main.tscn`：当前主场景，集中挂载玩家、世界、刷怪、战斗、任务、NPC 与 HUD。
- `scenes/actors/enemy.tscn`：敌人基础场景。
- `scripts/player/player_controller.gd`：角色移动、职业属性、经验等级、背包装备、材料、存档。
- `scripts/combat/combat_director.gd`：自动/手动战斗、索敌、技能施放、伤害、经验金币和掉落。
- `scripts/combat/enemy_controller.gd`：怪物 AI、精英变体、Boss 阶段和攻击预警。
- `scripts/world/isometric_world.gd`：等距地图绘制、区域、碰撞、寻路。
- `scripts/world/enemy_spawner.gd`：普通怪、精英与 Boss 刷新。
- `scripts/quest/quest_director.gd`：任务状态与奖励。
- `scripts/ui/battle_hud.gd`、`touch_controls.gd`：HUD、背包、NPC交互和触控输入。
- `docs/`：产品设计、技术架构、研发计划与路线图。

当前仓库规模仍是早期可玩原型：主场景集中组装，核心逻辑主要由 GDScript 承担；当前树中没有独立美术资源目录或完整角色/地图动画资源。

## 3. 经典传奇核心体验对标

| 体验维度 | 当前状态 | 审计判断 |
|---|---|---|
| 单角色成长 | 已有等级、经验、属性、职业切换 | 已建立基础 |
| 战法道职业 | 三职业属性和主动技能不同 | 已有雏形；每职业目前主要是一项主动技能 |
| 野外刷怪 | 自动索敌、追击、攻击、刷新 | 已建立；刷新点和怪物种类偏少 |
| 手动战斗 | 手动攻击入口、技能按钮 | 基础可用；目标选择、走位和技能组合深度不足 |
| 自动战斗 | 自动索敌、接敌、普攻 | 已有基础；需要明确可控范围、停止条件和风险反馈 |
| 装备爆落 | 品质、区域套装、精英保底、Boss专属 | 系统较完整；装备词条和职业适配还需深化 |
| 装备成长 | 金币强化、符文锻造、材料觉醒 | 已有三层成长；长期数值曲线尚未验证 |
| 地图推进 | 新手村、入口、密林、遗迹、祭坛 | 区域结构已建立；目前更像一张纵向连续测试地图 |
| NPC与任务 | 村长任务、铁匠、商人、传送向导 | 已建立基础交互 |
| 精英与Boss | 精英词缀、Boss血量阶段、范围预警 | 已建立；攻击模式和机制类型仍单一 |
| 离线存档 | 本地 JSON、自动保存、旧字段兼容 | 已有基础；备份、损坏恢复和版本迁移仍需专项验证 |
| 视觉表现 | 代码绘制地块、几何角色/NPC、基础特效 | 明显落后于成熟商业游戏；是当前最突出的体验短板 |
| Android体验 | 竖屏配置、虚拟摇杆和触控按钮 | 代码已具备；安装、触控、适配和帧率未做真机验收 |

## 4. 当前最值得优先处理的问题

### P0：视觉与交互验收
- 原型角色目前是蓝色几何方块，敌人和 NPC 也是基础几何图形。
- 地图主要由重复菱形地块和少量石块构成，缺少地表纹理、植被、道路、建筑、遮挡层次和区域地标。
- UI 采用固定像素坐标，尚未证明在不同 Android 长宽比、系统安全区和刘海屏上布局稳定。
- 主场景副标题仍包含开发测试文案 `P2 COMBAT TEST`，应在面向玩家的版本中清除。
- 原有 CI 只有 headless 导入和启动，不能发现按钮遮挡、文字溢出、画面空白、图层顺序和实际渲染问题。

### P1：世界与战斗内容
- 当前普通怪刷新点集中在林间入口、幽暗密林和古代遗迹；遗忘祭坛没有普通怪刷新点，主要依赖 Boss 刷新，区域内容密度不完整。
- 怪物视觉、动作、受击反馈、死亡表现和攻击招式缺乏差异。
- 三职业当前技能数量和战斗决策深度不足；技能成长、技能解锁与职业专精尚未形成完整循环。
- 地图需要从纵向测试场地逐步升级为有道路、岔路、资源点、刷怪营地、精英据点和首领场地的区域地图。

### P2：系统深度与产品化
- 装备已有品质、套装、词条、锻造和觉醒，但缺少可验证的掉落期望、装备评分解释和职业构筑目标。
- 缺少成体系的音效、背景音乐、环境反馈和设置项。
- 需要建立存档版本号、备份恢复、异常提示和跨版本迁移回归。
- 需要补齐 Android APK 安装、不同分辨率、安全区、触控热区、持续运行和性能测试。

## 5. 视觉检测方案

本次开始将 CI 从“只解析/启动”扩展为“实际渲染截图 + 基础图像有效性检查”：

1. 使用 Xvfb 与 Mesa 软件渲染，在 Linux CI 中启动 Godot 的 Compatibility 渲染器。
2. 运行视觉冒烟脚本，确认 Player、World、HUD、TouchControls 节点存在。
3. 捕获项目默认桌面窗口尺寸 540×960（9:16）的启动与背包画面；项目内部参考视口为 720×1280。
4. 检查截图非空、分辨率正确，并抽样检测画面像素变化，避免空白帧被误判为通过。
5. 将截图作为 GitHub Actions Artifact 保存 14 天，供人工逐帧检查布局、遮挡、视觉层级和表现问题。

说明：这属于视觉冒烟检测，不是 AI 美术审查，也不是与商业游戏截图的像素级相似度比较。它能发现空白渲染、场景节点缺失和部分 UI 状态问题；美术品质、操作手感、动画观感与 Android 真机适配仍需人工验收。

## 6. 首轮截图人工复核结果

已检查 CI 生成的启动与背包截图（默认窗口 540×960）：

- 启动画面仍显示旧的静态副标题 `THE FORGOTTEN GROVE | P2 COMBAT TEST`，与动态区域/货币信息挤在同一顶部信息带；已移除该开发占位标签。
- 背包面板原高度仅 380 逻辑像素，长装备/材料摘要和多个操作按钮会把面板内容挤出屏幕；已将面板扩展到适合竖屏的高度，并增加信息文本显示空间。
- CI 初次截图中的中文字体显示为缺字方框；这来自 Linux runner 缺少 CJK 字体，不代表 Android 或 macOS 的最终字体效果。CI 已增加 Noto CJK 字体安装，后续截图用于复核。
- 角色、怪物和 NPC 仍是几何占位图形；这不是截图工具的问题，而是当前美术资源尚未进入项目。

上述 UI 修正已合入代码；必须以本次修正后的新截图再次确认，不能仅凭代码修改认定视觉问题已经解决。

## 7. 建议开发顺序

1. **视觉基线**：先拿到稳定的启动/背包截图，修复开发占位文案、UI边界和层级问题。
2. **角色与怪物表现**：建立原创角色、怪物、攻击/受击/死亡动画规范，先替换几何占位。
3. **地图场景化**：为四个区域建立差异化地表、植被/遗迹地标、道路和刷怪营地；补齐祭坛普通怪刷新。
4. **职业战斗深化**：每职业增加技能成长与至少两种可选择战斗打法，完善目标选择、范围预警和技能反馈。
5. **装备构筑深化**：职业适配词缀、套装构筑目标、区域掉落期望与经济曲线。
6. **Android验收**：建立设备矩阵，测试分辨率、安全区、触控、帧率、发热、断网和存档恢复。

## 8. 验收原则

- 每次提交：Godot 4.7.2 导入、解析、主场景启动。
- 视觉提交：启动和背包截图必须生成并上传 Artifact。
- 玩法提交：至少验证对应功能的状态变化和异常路径。
- 发布候选：必须增加 Android 真机验收；CI 通过不等于真机通过。
